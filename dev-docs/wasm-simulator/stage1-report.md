## 4. 実装中に見つけて直したこと

計画のリスク欄になかったものが 3 つ。いずれも**ドキュメントだけでは分からず、
実際に動かして初めて出た**。

### 4-1. `<script type="text/ruby">` は 1 つずつ別タスクになる

`init.iife.js` を読むと `picorb_create_task` を script タグごとに呼んでいる。
タスクは協調スケジューリングなので、依存関係のある 3 ファイルを分けると順序が保証されない。

→ ページの JS が 3 ソースを `fetch` して連結し、インラインの
`<script type="text/ruby">` 1 つとして注入する。実ファイルを読む性質は保っている。

### 4-2. `JS.global.fetch` は `.then` ではなくブロックを取る

`fetch(url).then { }` と書いていて例外になり、`SimUI.setup` が途中で死んでいた。
結果としてテキストエリアが空のまま、Run しても何も起きない状態だった。

```ruby
JS.global.fetch(url) do |response|
  text = response.text.await
end
```

### 4-3. JS ブリッジは引数に Array を受け付けない

`JS.global.renderPanel(array)` が `TypeError: Unsupported argument type`。
`src/mruby/js.c` を読むと、対応しているのは
**String / Integer / Float / nil / bool / JS::Object のみ**。
interop ドキュメントの型対応表は `[]=` の話で、メソッド引数には当てはまらない。

→ フレームを **16 進文字列 1 個**（512 文字）で渡す。
`JS::Bridge.to_js` でも変換できるが 256 要素を 1 個ずつ push するので、
「1 フレーム 1 呼び出し」という目的に反する。
生バイト列にしないのは、ブリッジが C 文字列として扱うため**消灯 = NUL で切れる**から。

### 4-4. `LedMatrix` を JS 非依存側へ移した（計画より良くなった）

当初 `sim_ui.rb` に置く想定だったが、それだとブラウザが操作する座標変換が
ヘッドレス検証の対象外になる。`sim_panel.rb` へ移し、
テストも**ページと同じ `LedMatrix` を駆動する**ようにした。

## 5. 検証環境で見つかった落とし穴（仕様どおりだが紛らわしい）

「初期化忘れ」サンプルを実行すると、**その後のサンプルで上半分が光らなくなる**。

原因は仕様どおり: このサンプルは上半分のチップに `reset`（0xCF ← 0xAE）を送るので、
チップは本当に POR 状態（GCC も Scaling も 0）へ戻る。
一方 `matrix.top` のドライバオブジェクトは設定済みのつもりのままで、
以後 PWM を書いても光らない。**実機でも同じことが起きる。**

対応: サンプルにその旨と「Reset ボタンで戻る」を明記し、
検証ハーネスはサンプルごとに Reset を挟むようにした。

## 6. 検証環境

```console
rake sim:check              # 全サンプルを実行して結果を報告
rake sim:check[l_shape]     # 1 つだけ
rake sim:browser_image      # イメージを作り直す
```

- **ファーム用とは別のイメージ**（`docker/browser.Dockerfile`）。
  Node も Chromium もファームのビルドには要らないため
- 静的サーバもコンテナ内で立てるので、ポート公開やネットワーク設定は不要
- 報告するもの: ステータス欄の文言、**canvas から読み戻した 16×16 のテキスト**、
  console 出力、ページエラー、リクエスト失敗。
  スクリーンショットは `tmp/browser-check/`（git 管理外）
- 終了コードはエラーがあれば非ゼロ

ハマったところ（Dockerfile にコメントあり）:

- ESM の `import` は `NODE_PATH` を見ない（importing file から上へ辿るだけ）。
  ハーネスは CommonJS にした
- `playwright install` はインストールしたユーザの HOME 配下に置く。
  実行時は別ユーザ・別 HOME になるので `PLAYWRIGHT_BROWSERS_PATH` で固定した

## 7. 既知の制限

| 項目 | 内容 |
|---|---|
| フォント・図形 | `picoruby-shinonome` / `picoruby-vram` は C 拡張で stock の wasm に入っていない。Stage 2 で自前ビルドが要る |
| アニメーション | サンプルはすべて静止画。`setTimeout` を使う例はまだ書いていない（ハーネスがあるので今なら検証できる） |
| 上下・左右の向き | シミュレータは「y=1 が上、x=1 が左」と決め打ち。物理的にどちらが上かは実機で 1 ドット点灯するまで未確定 |
| 輝度モデル | `pwm × gcc × scaling` の線形近似。実機の見え方（拡散板込み）とは異なる |
| エラーの行番号 | ソース連結のため、実行時エラーの行番号がずれる |
