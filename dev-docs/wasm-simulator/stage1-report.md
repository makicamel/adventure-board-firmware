## 4. 計画からの変更点

実装中に判明した事実による変更が 3 つ。

### 4-1. スクリプトは 1 タスクに束ねた（計画のリスク欄が的中）

`init.iife.js` を読んだところ、**`<script type="text/ruby">` は 1 つずつ
別の mruby タスク**になる（`picorb_create_task`）。タスクは協調スケジューリングなので、
3 つに分けると依存関係のある定義が揃う保証がない。

→ `index.html` の JS が 3 つのソースを `fetch` して**連結し、
インラインの `<script type="text/ruby">` 1 つとして注入**する形にした。
実ファイルを読む性質は保っている。

副作用: 実行時エラーの行番号が連結後のものになる。

### 4-2. `require 'i2c'` の手当てが必要だった（計画に無し）

ドライバ冒頭の `require 'i2c'` は、実機では組み込み gem に解決されるが、
`bin/picoruby` にもブラウザにもその gem が無く `LoadError` になる。

→ `sim_panel.rb` の先頭で `Kernel#require` を包んで `LoadError` を握りつぶす。
**picotest のランナーが同じ理由で同じことをしている**ので、この repo では既定の作法。
このため `sim_panel.rb` はドライバより**先に**読む必要がある。

### 4-3. `LedMatrix` を JS 非依存側へ移した（計画より良くなった）

当初 `sim_ui.rb` に置く想定だったが、それだとブラウザが操作する
`LedMatrix#set` の座標変換がヘッドレス検証の対象外になってしまう。
`sim_panel.rb` へ移し、テストも**ページと同じ `LedMatrix` を駆動する**ようにした。

- ブラウザのコンソール（CDN の読み込み失敗、fetch の失敗が出る）
- ステータス欄の文言（ソース読み込み失敗ならその旨が出る）

## 6. 既知の制限

| 項目 | 内容 |
|---|---|
| フォント・図形 | `picoruby-shinonome` / `picoruby-vram` は C 拡張で stock の wasm に入っていない。Stage 2 で自前ビルドが要る |
| アニメーション | サンプルはすべて静止画。`setTimeout` を使う例は私の環境で検証できないため入れていない |
| 上下・左右の向き | シミュレータは「y=1 が上、x=1 が左」と決め打ち。物理的にどちらが上かは実機で 1 ドット点灯するまで未確定 |
| 輝度モデル | `pwm × gcc × scaling` の線形近似。実機の見え方（拡散板込み）とは異なる |
| エラーの行番号 | ソース連結のため、実行時エラーの行番号がずれる |
