# Stage 1 実装計画

親計画: [README.md](README.md)

## 1. 目的

**`netlist.ipc` から導出した座標マッピングが正しいことを、目で確かめられるようにする。**

ドライバ本体は 20 テスト / 52 アサーションで固まっているが、
それはレジスタの符号化を固定しただけで、
**2 チップを 16×16 に合成したときに絵が正しく出るかは一度も確認されていない**。
とくに U11 側の列反転 `cs = 17 - c` は、間違っていても
「下半分だけ左右が逆」という形でしか現れず、テストでは気づけない。

## 2. スコープ

### やること

- ブラウザで実ドライバ（`mrblib/is31fl3729.rb`）を**改変なしで**動かす
- 仮想 IS31FL3729 が**実際のレジスタ書き込みをデコード**する
- 2 チップを 16×16 に合成して描画する
- テキストエリアに書いた Ruby をその場で実行できる

### やらないこと（Stage 2 へ）

- フォント描画（`picoruby-shinonome`）
- VRAM の描画 API（`picoruby-vram`）
- 実機 R2P2 との通信

どちらも C 拡張で、stock の `@picoruby/wasm-wasi` には入っていないため。

## 3. 設計

```
                        ブラウザ
  ┌──────────────────────────────────────────────┐
  │ index.html                                   │
  │   canvas 16×16  +  コードエディタ  +  Run    │
  │   renderPanel(values)  ← 描画だけ JS         │
  └────────────────┬─────────────────────────────┘
                   │ JS interop
  ┌────────────────┴─────────────────────────────┐
  │ sim_ui.rb        JS グルー（canvas / 入力）  │
  ├──────────────────────────────────────────────┤
  │ sim_panel.rb     ★純 Ruby・JS 非依存         │
  │   class I2C                 write を仮想バスへ│
  │   class VirtualIS31FL3729   レジスタをデコード│
  │   class Panel               2チップ→16×16    │
  ├──────────────────────────────────────────────┤
  │ is31fl3729.rb    ★リポジトリの実ファイル      │
  └──────────────────────────────────────────────┘
```

### 判断とその理由

**`sim_panel.rb` を JS 非依存の純 Ruby にする。**
面白い部分（レジスタのデコードと座標合成）がブラウザ無しで検証できるようになる。
ブラウザでしか確認できないことを最小化するための分割。

**描画だけ JS 関数 1 つに寄せる。**
256 セルを Ruby から個別に触ると JS 呼び出しが 1 フレームあたり数百回になる。
`renderPanel(values)` に 256 要素の配列を 1 回渡す形にすれば呼び出しは 1 回で済む。
シミュレーションのロジックは Ruby 側に残る。

**ドライバはリポジトリの実ファイルを読む。**
`<script type="text/ruby" src="/mrbgems/picoruby-is31fl3729/mrblib/is31fl3729.rb">`。
コピーを置くと本物と乖離するため、サーバのルートをリポジトリルートにする。

### 仮想チップが再現すること

| 挙動 | 理由 |
|---|---|
| アドレス自動インクリメント | ドライバの一括転送が前提にしている |
| PWM レジスタ 0x01〜（rows×16 バイト） | 座標マッピングの検証対象そのもの |
| `SSD` ビット（0 なら全消灯） | 初期化忘れの再現 |
| `GCC`（0xA1）と Scaling（0x90〜0x9F） | **POR で両方 0 = 光らない**を再現する |
| Reset（0xCF ← 0xAE） | 全レジスタが POR に戻る |

輝度は `pwm/255 × gcc/64 × scaling/255` で 0.0〜1.0 に落とす。
実機の見え方の近似であって、光学的な正確さは狙わない。

## 5. 検証

### ヘッドレスで確認できること（私が実行する）

`bin/picoruby sim/test/panel_test.rb` を Docker 内で実行。

1. 実ドライバ 2 個 + 仮想チップ 2 個で、`(x, y)` を指定して点灯させると
   **その座標だけが光る**（256 点すべて）
2. **U11 の列反転**が効いていること
   （下半分で `x=1` に点けたら、チップには `cs=16` が書かれている）
3. 行 8 と行 9 の境界でチップが切り替わること
4. GCC / Scaling が 0 のままだと**光らない**こと
5. `SSD=0` で全消灯すること
6. 既知のパターン（例: `L` 字）を投入して、期待する 16×16 の絵と一致すること

### ブラウザでしか確認できないこと（検収でお願いする）

- ページが読み込まれ、canvas に 16×16 が出る
- テキストエリアの Ruby を Run すると絵が変わる
- CDN の `@picoruby/wasm-wasi` が実際に動く
- 複数の `<script type="text/ruby">` が**読み込み順に実行される**
  （ドライバ → sim_panel → sim_ui の順に依存しているため。
  もし順序が保証されなければ 1 ファイルに束ねる）

## 7. リスクと退避策

| リスク | 退避策 |
|---|---|
| 複数の `text/ruby` スクリプトの実行順が保証されない | 1 ファイルに束ねる。ドライバはビルド時ではなく手で連結せず、`sim_ui.rb` から `JS.global.fetch` で読む手もある |
| CDN の `@latest` が壊れる / API が変わる | バージョン固定タグに切り替える |
| `eval` が wasm ビルドに無い | `stdlib` gembox に `mruby-eval` が入っていることは確認済み。無ければ `PicoRubyVM::InstructionSequence` 経由に変更 |
| 256 セル描画が遅い | 描画は JS 関数 1 呼び出しに集約済み。それでも遅ければ変更のあったセルだけ描く |
