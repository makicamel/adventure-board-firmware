## 1. 構成

| 項目 | 値 |
|---|---|
| ドライバIC | IS31FL3729 ×2（U10, U11）、QFN-32、LCSC C2940549 |
| LED | 白色 256個（16×16）、0402、**ピッチ 1.6mm**、LCSC C20613596、**VF 約 3.0〜3.2V** |
| マトリクス寸法 | 24.0mm × 24.0mm（15ピッチ × 1.6mm） |
| 分割 | U10 = 行1〜8、U11 = 行9〜16（列は32本に完全分離） |
| IC電源 | **5V**（U10/U11 pin23 → `5V` ネット） |
| ISET | R17/R18 = 33kΩ → ピーク約10.3mA、行電流 約165mA、全点灯 330mA のハード上限 |

> R39/R40 は DNP の THT パッド（"33k (opt)"）。明るさを変えて試すときは
> SMD の R17/R18 を剥がして R39/R40 に足付き抵抗を挿す運用。

## 2. 5V 駆動について — 問題ない

データシートの `VCC = 2.7〜5.5V` の範囲内。**5V にしたのはヘッドルーム問題の
解決策そのもので、3.3V 案が成立しなかったことへの答え**。

白色 LED の VF ≈ 3.1V、VCC = 5V なので、IC 内部で落ちるのは約 1.9V。
一方、電流レギュレーションに必要な最低ヘッドルームはこれよりはるかに小さい。

データシート ELECTRICAL CHARACTERISTICS の `VHR` は次の条件での値:

| 項目 | 規定条件 | typ | max |
|---|---|---|---|
| SWx（行スイッチ側） | **ISWITCH = 600mA**、RISET=10kΩ、GCC=0x40、SL=0xFF | 500mV | 550mV |
| CSx（列シンク側） | **ISINK = 34mA**、RISET=10kΩ、GCC=0x40、SL=0xFF | 400mV | 500mV |

本基板は RISET = 33kΩ なので、列シンクは 10.3mA（規定の約0.30倍）、
行スイッチは16列同時でも約165mA（規定の約0.28倍）。ヘッドルームは
オン抵抗による降下なのでほぼ電流に比例し、合計 1050mV ではなく **300mV 程度**。
1.9V の余剰に対して桁違いに小さく、余裕は十分。

> `docs/led_research_results.md` の「白色は5Vでも余裕+0.30V」は、
> **IC を最大電流で使ったとき**の最悪値（1050mV）から引いた数字で、
> RISET=33kΩ の本基板には当てはまらない。

**実際の論点はヘッドルームではなく発熱**で、これは基板側で解決済み:

- IC の損失 = 1.9V × 165mA ≈ **0.31W/個**、ΔT ≈ 15〜16°C。許容範囲
- データシート Typical 回路にある CS の 20Ω 直列抵抗は
  「IC から熱を逃がすためのオプション」で、**本基板では不採用**
- LED 直列抵抗も不要（定電流駆動のため）

> **EP 直下のサーマルビアは r1 には入っていない。** xlsx でも当該行は「要確認」のまま。
> netlist を実測したところ U10/U11 の EP（±1.4mm）内にビアは 0 本、
> 最寄りの GND ビアは U10 で 3.2mm、U11 で 3.09mm 離れている。
> ただし本基板は **4層**（F_Cu / In1_Cu / In2_Cu / B_Cu）で EP は GND ベタに落ちており、
> GND スティッチビアが 228 本（平均間隔 3.6mm）打たれている。
> 0.31W ならこの経路でも十分逃げるので**実用上の問題はない**見込み。
> 次版があれば EP 下に 4〜9 本入れると余裕が増える、という程度。

ロジックは 3.3V 直結でよい。I2C プルアップが 3V3 かつ 3.3V ≥ 3.0V なので
データシート Note 1 のレベルシフト推奨条件にも該当しない。

## 3. RP2350A との接続

| 信号 | GPIO | U1 ピン | 経路 |
|---|---|---|---|
| I2C0 SDA | **GPIO4** | 7 | R48（0Ω）→ `SDA0`。R11 2.2kΩ で 3V3 プルアップ |
| I2C0 SCL | **GPIO5** | 8 | R49（0Ω）→ `SCL0`。R12 2.2kΩ で 3V3 プルアップ |
| SDB（イネーブル） | **GPIO24** | 36 | U10/U11 pin29 に直結。R13 4.7kΩ プルダウン、C37/C38 100nF |

- R48/R49 は I2C デバッグ用のカットポイント。外すと MCU を LED バスから切り離せる
- R13 が 4.7kΩ なのは **RP2350 erratum E9 対策**。入力モードで最大120µA
  リークするため 100kΩ では 0V に引けず約2.2V にラッチし、
  IS31FL3729 の VIH min=1.4V を超えてシャットダウンが効かなくなる。公式推奨は 8.2kΩ 以下

### 3-1. ★SDB のタイミング要件（ファーム必須）

C37 + C38 = **合計 0.2µF** が SDB に載っている。GPIO で充電するため、

- **SDB を H にしてから 200µs 程度待ってから最初の I2C トランザクションを出す**
  （データシート Note 8 の 10µs では足りない）
- **停止時は I2C を止めてから 200µs 空けて SDB を L にする**

### 3-2. SDB は I2C バス復旧に使える

SDB の立ち上がりで I2C バスがリセットされる仕様。バスがハングしたときに
SDB をトグルすれば **U10/U11 両方の I2C 状態機械を初期化できる**。
ドライバに復旧 API を用意しておく価値がある。

### 3-3. I2C アドレス

AD ピン（pin28）で決まる。データシート Table 1 で `A7:A3 = 01101`:

| チップ | AD 接続 | 7bit アドレス |
|---|---|---|
| **U10** | GND | **0x34** |
| **U11** | SCL0 | **0x35** |

## 4. 座標マッピング（r1 netlist + positions.csv から確定）

### 4-1. ネットの構造

- 行: `MTX_R1` 〜 `MTX_R16`（16本）
- 列: `MTX_CA1`〜`MTX_CA16`（U10用）、`MTX_CB1`〜`MTX_CB16`（U11用）の32本
- **`MTX_CA<n>` と `MTX_CB<n>` は同じ物理列**（実装座標の X が一致することを確認済み）。
  2チップで CS を共有できないため、同じ列に別ネットを引いてある

256個すべてが一意の (列, 行) に収まる完全な 16×16 であることを検証済み:

| ネット | 座標 |
|---|---|
| MTX_CA1 / MTX_CB1 | X = 123.0 mm |
| MTX_CA5 / MTX_CB5 | X = 129.4 mm（1.6mm ピッチ） |
| MTX_CA16 / MTX_CB16 | X = 147.0 mm |
| MTX_R1 | Y = −49.98 mm |
| MTX_R16 | Y = −73.98 mm（1.6mm ピッチ） |

### 4-2. チップピンとの対応

データシート PIN DESCRIPTION:
`1〜8,10〜13 = CS4〜CS15` / `9,24 = GND` / `14 = SW9/CS16` / `15〜22 = SW8〜SW1` /
`23 = VCC` / `25 = ISET` / `26 = SDA` / `27 = SCL` / `28 = AD` / `29 = SDB` / `30〜32 = CS1〜CS3`

netlist と突き合わせた結果:

| | 行 | 列 |
|---|---|---|
| **U10 (0x34)** | SW n → `MTX_R n`（n=1..8） | CS n → `MTX_CA n`（**そのまま**） |
| **U11 (0x35)** | SW n → `MTX_R (n+8)`（n=1..8） | CS n → `MTX_CB (17 − n)`（**左右反転**） |

U11 の列だけ反転しているのは配線の都合。**ファームで必ず補正が要る。**

### 4-3. 実装すべき変換

```ruby
chip = (r <= 8) ? 0x34 : 0x35          # U10 / U11
sw   = ((r - 1) % 8) + 1               # 1..8
cs   = (r <= 8) ? c : (17 - c)         # U11 は列反転
reg  = (sw - 1) * 0x10 + cs            # PWM レジスタアドレス
```

残る不定は**上下・左右の向きだけ**。実機で1ドット点灯すれば決まる。

## 5. レジスタマップ（データシート Table 5）

| アドレス | 名前 | POR値 |
|---|---|---|
| 0x01–0x8F | PWM Register（ドットごとの8bit輝度） | 0x00 |
| 0x90–0x9F | Scaling Register（CS列ごとのピーク電流） | 0x00 |
| 0xA0 | Configuration Register | 0x00 |
| 0xA1 | Global Current Control (GCC) | 0x00 |
| 0xB0 | Pull Down/Up Resistor Selection | 0x33 |
| 0xB1 | Spread Spectrum | 0x00 |
| 0xB2 | PWM Frequency | 0x01 |
| 0xB3–0xC4 | Open/Short Register（読み出し） | 0x00 |
| 0xCF | Reset（**0xAE を書くと POR 状態へ**） | — |

### 5-1. Configuration Register (0xA0)

| ビット | D7:D4 | D3 | D2:D1 | D0 |
|---|---|---|---|---|
| 名前 | SWS | LGC | OSDE | SSD |

- `SSD` = 1 で通常動作。**POR は 0 なので明示的に 1 を書く必要がある**
- `SWS` = `0b0001` … n=8、SW1〜SW8 × CS1〜CS16。**この基板の構成**
  （このモードで pin14 の `SW9/CS16` が CS16 として働く）
- `PWM 最小 duty（1/255）は U10 と U11 で明るさが目視で違う`（チップ個体差。
  [device-bringup/r1-board.md](../device-bringup/r1-board.md) の「明るさの見え方」）
- `LGC` … 0 で VIH/VIL = 1.4V/0.4V、1 で 2.4V/0.6V。
  **★実チップで確認: LGC を 0→1 にした書き込みの直後の 1 トランザクションは
  必ず NACK される**（データシートに記載なし。20ms 空けても同じ）。落ちたのが
  書き込みだと、その後しばらく読み出しが 1 トランザクション遅れて返る。
  gem は `configure` で LGC を立てた直後に捨て読みを 1 回入れて吸収している
- `OSDE` … 01/11 で開放検出、10 で短絡検出。実装検査に使える

### 5-2. PWM レジスタのアドレス

Figure 9 より `addr(sw, cs) = (sw - 1) * 0x10 + cs`（sw=1..8, cs=1..16）。

- `(SW1,CS1)` → 0x01、`(SW1,CS15)` → 0x0F、`(SW1,CS16)` → **0x10**、`(SW8,CS16)` → 0x80
- **1行 = 16バイト連続**、8行で 0x01〜0x80 が隙間なく並ぶ
- アドレス自動インクリメント対応なので、**0x01 から 128 バイトを1トランザクションで
  一括転送できる**。16×16 フル更新が I2C 2回で済む

### 5-3. 電流の式

```
IOUT(PEAK) = 342 / RISET × (GCC / 64) × (SL / 256)
```

GCC（0xA1、0〜0x40）と SL（Scaling、0x90〜0x9F）は **POR で両方 0**。
どちらも設定しないと一切光らない。

## 5-4. ★電源バジェットはファームの責任

ハードは全点灯電流を止めてくれない。

| 経路 | 値 |
|---|---|
| LED マトリクス全点灯 | 330mA（ISET 33kΩ によるハード上限） |
| MCU + Flash + ロジック | 約 100mA |
| 音声アンプ最大音量 | +300mA |
| **最悪同時** | **約 730mA** |
| USB の供給 | 500mA |

5V レールは U7 TPS2065CDBV 経由だが、その電流制限は **連続1A / トリップ typ1.55A**。
xlsx にも「**USB の 500mA 制限を担保するものではない（突入電流と短絡の保護が目的）**」
と明記されている。つまり 730mA を引いても TPS2065 は落ちない。

**したがってファーム側で:**

- GCC の初期値を低くする（全点灯150mA相当あたりから始める）
- 音声を鳴らしている間はマトリクスの明るさを絞る
- 応用: 点灯ピクセル数をカウントして、少ないときだけ電流を上げる適応制御。
  点灯率25%なら4倍の電流を許容できる

## 6. 失効した GPIO 文書について

`docs/gpio_assignment.md`（2026-07-27「承認済み」）は、2026-08-18 の
**「PRB寄せ改訂」**で大きく書き換えられている。PicoRuby Board (PRB) と
ピンを揃えて既存コードがそのまま動くようにする、という意図の変更。

| 機能 | gpio_assignment.md | 現行（xlsx / r1） |
|---|---|---|
| LEDドライバ I2C0 | GPIO4 / GPIO5 | GPIO4 / GPIO5 ✅据置 |
| **LEDドライバ SDB** | GPIO14 | **GPIO24** |
| GROVE-A I2C1 | GPIO2 / GPIO3 | **GPIO6 / GPIO7** |
| ボタン SW1〜SW6 | GPIO6〜11 | **GPIO17〜22**（10kプルアップ R33〜R38） |
| 音声PWM | GPIO12 | **GPIO10** |
| アンプ SD | GPIO13 | **GPIO23** |

LED マトリクス gem に効くのは SDB の 1点だけだが、音声・ボタン・GROVE の
gem を作るときは必ず xlsx 側を見ること。

## 7. 実機ブリングアップ時の注意

1. **J2（SWD/UART ヘッダ）は DNP** — JLCPCB では実装されない。
   PicoProbe で焼く/デバッグするには 2.54mm ピンヘッダを自分で付ける必要がある。
   BOOTSEL（SW7）は実装されるので文鎮化はしない
2. **上下・左右の向き** — §4-3 の通り、残るのは向きだけ。1ドット点灯で確定
3. **B0h（デゴースト用プルアップ/プルダウン）** — POR 値 0x33（2kΩ）のままで
   よいかは実機の残光を見て調整
4. **LED241 を重点チェック** — xlsx に「`MTX_R16` の配線と LED241 のパッド1
   （`MTX_CB1`）が 0.125mm。幾何計算では規則 0.15mm を下回るが KiCad の DRC では
   検出されない」とある。LED241 は **列1・行16**（マトリクスの角）、
   ドライバ座標では **U11 (0x35) / SW8 / CS16 → PWM レジスタ 0x80**。
   開放/短絡検出（0xB3〜0xC4）を使う検査スクリプトを書けば自動で拾える
5. GPIO は 29/30 本使用済み。**空きは GPIO15 のみ**
